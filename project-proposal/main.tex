\section{Introduction and Problem Statement}

Large Language Model (LLM) coding assistants such as Cursor, Claude Code, and
Codex have rapidly become part of everyday software development. These tools
work by sending a developer's source code and instructions to a hosted LLM,
which is billed per \emph{token} (a small fragment of text). As a project or
team grows, the number and size of these requests grow with it, and so does the
bill.

In practice, a large share of this spend is avoidable. Coding agents routinely
attach big portions of a codebase to \emph{every} request, re-send
near-identical prompts, and include files the model does not actually need for
the task at hand. This creates three problems: (i)~unpredictable and rapidly
growing API bills; (ii)~unnecessary exposure of private source code to
third-party providers; and (iii)~the absence of any standard control layer to
manage either. Existing ``prompt-compression'' tools treat code as plain text
and cut it by length or pattern. This is unsafe: they can silently delete a line
of logic the model needs, breaking correctness.

This project proposes \textbf{AI Cost Autopilot}, a lightweight,
provider-agnostic gateway that sits between a coding agent and the LLM and
reduces cost on every request through three cooperating components: a
\emph{compiler-aware trimmer} that understands code structure and sends only
what is needed; a \emph{semantic cache} that reuses answers to questions that
mean the same thing; and an \emph{autopilot} policy that selects the cheapest
safe action per request. We have already validated the core hypothesis with a
proof-of-concept: routing the open-source TestZeus/Hercules agent through a
proxy with off-the-shelf prompt compression cut token usage by roughly 25\% with
no observable change in the agent's behaviour across repeated runs. This
proposal covers building our own, purpose-built, and safer system.

\section{Objectives}

\noindent\textbf{Primary goal:} Design and build a provider-agnostic gateway
that measurably reduces the token cost of LLM coding agents on repetitive,
code-heavy workloads, without changing agent behaviour. Specific,
time-bound sub-goals:

\begin{itemize}[noitemsep]
  \item Implement a \textbf{compiler-aware trimmer} for at least one language
        (Python) that uses AST analysis to keep needed code in full and collapse
        the rest to signatures.
  \item Implement a \textbf{semantic cache} using embeddings, with a tuned
        similarity threshold and a secret/PII filter.
  \item Implement an \textbf{autopilot} policy that selects reuse, trim, or
        pass-through per request.
  \item Integrate all three behind a single \textbf{OpenAI/Anthropic-compatible}
        endpoint that existing tools connect to by changing one setting.
  \item \textbf{Evaluate} token savings ($\geq$ 30\% target on code-heavy
        repetitive workloads), cache hit-rate, and behavioural equivalence on the
        TestZeus/Hercules agent by W17.
\end{itemize}

\section{Methodology and System Architecture}

\subsection{System Architecture and Tech Stack}
The system is a proxy exposing an OpenAI- and Anthropic-compatible
\texttt{/v1/chat/completions} endpoint, so any coding agent connects by changing
a single base-URL setting. It is implemented in \textbf{Python} using
\textbf{FastAPI} (web service) and \textbf{httpx} (forwarding to the provider),
with token accounting via \textbf{tiktoken}. Responses are streamed back to the
client, and tool/function-call structures are preserved unchanged so agentic
tools keep working.

\subsection{Module Development}
\begin{itemize}[noitemsep]
  \item \textbf{Compiler-Aware Trimmer (Agam).} Uses \texttt{tree-sitter} to
        parse code into an Abstract Syntax Tree, builds a dependency graph, keeps
        the focus file plus its 1--2 hop dependencies in full, and collapses all
        other functions/classes to their signatures. It is deterministic and
        never breaks syntax. Python first, then TypeScript.
  \item \textbf{Semantic Cache (Devansh).} Uses \texttt{sentence-transformers}
        embeddings and a vector store (SQLite\,+\,NumPy or FAISS). Each request is
        embedded and matched against stored requests by cosine similarity; on a
        match above a tuned threshold, the stored answer is returned. Includes
        per-user isolation, a time-to-live, and a filter that refuses to cache
        secrets or personal data.
  \item \textbf{Autopilot Policy (Furmaan).} For each request it runs a safety
        check, then a cache lookup, then decides between trimming and pass-through
        using cheap signals (token count, presence of code). Conservative
        thresholds prevent serving a ``close-enough'' but wrong cached answer.
\end{itemize}

\subsection{Testing and Validation}
Each module ships with unit tests, and an integration test exercises the full
pipeline end-to-end. We validate on the open-source \textbf{TestZeus/Hercules}
agent, measuring: (i)~percentage token reduction, (ii)~cache hit-rate,
(iii)~dollar cost per run, and (iv)~\emph{behavioural equivalence} --- confirming
the agent reaches the same outcome with and without the gateway across repeated
runs. Success criteria: $\geq$ 30\% token reduction on code-heavy repetitive
workloads with \textbf{zero} behavioural regressions.

\section{Resources and Team Roles}

\textbf{Team roles.} Agam --- compiler-aware trimmer; Devansh --- semantic cache;
Furmaan --- autopilot policy. The gateway and the evaluation harness are shared,
with pull-request review across the team.

\textbf{Software (all open-source / free).} Python, FastAPI, httpx,
tree-sitter, sentence-transformers, FAISS/SQLite, tiktoken, and pytest;
Git and GitHub for version control and collaboration.

\textbf{Compute and budget.} Development runs on the team members' personal
laptops. A small amount of LLM API credit (estimated under a few hundred rupees
on a low-cost model such as \texttt{gpt-4o-mini}) is needed for benchmarking. No
external funding is required; all other resources are freely available through
open-source tooling and the university.

\section{Risks and Mitigation}

\begin{itemize}[noitemsep]
  \item \textbf{Language-specific parsing is complex.} Start with Python, add
        languages incrementally, and fall back to safe generic trimming when a
        file cannot be parsed.
  \item \textbf{The cache could return a wrong ``close'' answer.} Use a
        conservative similarity threshold plus behavioural-equivalence checks, and
        never cache sensitive content.
  \item \textbf{Provider APIs may change.} Isolate provider specifics behind a
        thin adapter layer.
  \item \textbf{Scope creep.} Follow a milestone-driven plan: one language and
        one provider first, then expand.
\end{itemize}
